## 3. Como operar (trampas del entorno)
- Termux aarch64, 10 nucleos Cortex-A520, 7.2 GB RAM + 4 GB swap (RAM Plus de Samsung; se puede subir a 8 GB en Ajustes>Cuidado del dispositivo>Memoria>RAM Plus, requiere reiniciar y mata todo). Swap lleno => el contenedor SE REINICIA (ya paso ~5 veces; los archivos persisten, los procesos no).
- Godot SIEMPRE: grun ~/tools/godot-4.7-stable/Godot_v4.7-stable_linux.arm64 --headless --path ~/UNTITLED --script res://tests/X.gd. Godot devuelve exit 0 aunque no compile: comprobar SCRIPT ERROR y PASS. ~/.local/bin/grun limita Godot a 2 a la vez (solo si el comando contiene Godot_v; opencode tambien pasa por grun y NO se limita).
- Scripts con shebang no funcionan: bash script. NUNCA pkill -f con texto presente en el propio comando (mata tu shell): usa pgrep -f 'bash [s]ched.sh' y kill por numero. NUNCA editar sched.sh/launch7.sh con ellos corriendo: kill PID, editar, relanzar.
- opencode run: --auto, briefs dentro de UNTITLED/briefs, mensaje corto que apunta al brief, sin subagentes ni Explore, lanzar escalonado (>=40 s) o 'database is locked'.
- PLANIFICADOR (reactivar tras reinicio): cd ~/untitled-control && : > sched.log && setsid nohup bash sched.sh </dev/null >/dev/null 2>&1 &   (MAX 2-3 dinamico segun swap<2800 y RAM, no lanza si swap>3400 o hay Gradle; prioridad estricta; V1 Gradle solo). Terminada = cycle2/<tarea>.exit con 0; borrar el .exit relanza. Monitor silencioso: tail -n 0 -F ~/untitled-control/sched.log | grep -E 'TERMINO|ABANDONADO|COLA VACIA'.
- Export Android: tools/build_android.sh (termux-chroot por /tmp). Export VR: tools/build_vr.sh (Gradle con --no-daemon, doNotStrip, aapt2 nativo). CIERRE VR: tools/finish_vr.sh (aborta si hay agentes; corre tests clave, build_vr, apksigner, check_compile en build/vr_project, copia a Descargas). El APK se compila desde una COPIA: si un agente edita un archivo a mitad, el APK sale roto (paso con el de las 19:45): comprobar con tools/check_compile.gd (bad=0).
